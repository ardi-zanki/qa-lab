# BUG-001 Kode valid yang diawali nol ditolak

**Dampak.** Pada mode legacy, pengguna dengan kode yang diawali nol tidak bisa
menyelesaikan persetujuan meskipun memasukkan kode yang benar. Permintaan tetap
berstatus pending. Alur dengan kode standar tetap berfungsi.

## Reproduksi

1. Nyalakan server dengan `APPROVAL_LEGACY_BUG=1 npm start`.
2. Buat permintaan dengan fixture **Code with leading zero**.
3. Isi kode `042731` dan klik **Approve document**.

**Hasil yang diharapkan.** API mengembalikan `200`. UI menampilkan
`Status: Approved` dan mencantumkan waktu persetujuan.

**Hasil yang ditemukan.** API mengembalikan `422 INCORRECT_CODE`. UI menampilkan
pesan kode salah dan status tetap pending.

## Membedakan bug aplikasi dari masalah tes

1. Jalankan `npm run test:bug` lalu buka
   `npm run report -- playwright-report-legacy`.
2. Buka trace pada tes browser. Di panel **Network**, pilih
   `POST /api/requests/{id}/approve`. Periksa bahwa payload memuat
   `{"code":"042731"}` sebagai string dan server merespons `422`.
3. Bandingkan dengan tes API dalam run yang sama. Tes ini mengirim kode langsung
   ke server dan juga mendapat `422`, sehingga masalah dapat direproduksi tanpa
   interaksi browser.
4. Periksa perbandingan kode di `app/server.js`. Konversi
   `String(Number("042731"))` menghasilkan `"42731"`. Mode fixed
   membandingkan kode langsung sebagai string.

Jika langkah klik berhenti karena locator tidak menemukan tombol dan tidak
ada request persetujuan di Network, periksa locator dan keadaan halaman lebih
dulu. Bukti itu belum menunjukkan kegagalan API.

## Retest

Jalankan `npm test` pada mode fixed. Dua tes bertanda `@leading-zero` harus
lulus. Periksa juga kode salah, format salah, dan pengiriman ulang untuk
memastikan perbaikan tidak mengubah perilaku skenario lain.
